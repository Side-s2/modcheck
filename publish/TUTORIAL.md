# modcheck 使用教程

## 1. 准备检查

准备好服务端的 `mods` 文件夹、目标 Minecraft 正式版本和服务端加载器。本程序支持 Fabric、NeoForge 和 Forge，从 Modrinth 查询模组，并从 Mojang 读取正式版列表。

将 Windows 便携压缩包完整解压，再双击 `启动GUI.cmd`。清单、设置与缓存通常保存在程序目录下的 `config` 文件夹。程序目录不可写时，会使用当前用户的配置目录。

### mods 文件夹的完整路径

通常在服务端根目录下，与 `server.jar` 同级，例如 `C:\servers\survival\mods`。

找不到时，可以这样确认：

- 查看启动脚本（`.bat` / `.sh`）：里面有 `-jar`、`nogui` 之类的行，脚本所在目录一般就是服务端根目录。
- 查看服务端根目录下有没有名为 `mods` 的文件夹。
- 客户端整合包的模组在 `.minecraft\mods`，位置形如 `C:\Users\你的用户名\AppData\Roaming\.minecraft\mods`。请注意：本工具检查的是**服务端实际加载的**模组。

### 服务端加载器

只能是 Fabric、NeoForge、Forge 之一，必须与你服务端实际使用的一致。判断方法：

- mods 文件夹里的 jar 文件名通常带加载器后缀，例如 `-fabric`、`-neoforge`、`-forge`。
- 服务端根目录的文件也能看出线索，例如 `fabric-server-launch.jar`（Fabric）、`user_jvm_args.txt` 与 `libraries` 目录（NeoForge / Forge 常见）。
- 服务端启动日志开头会写明加载器与版本。

## 2. 建立或导入清单

1. 选择「清单 → 扫描 mods 文件夹…」，添加至少一个文件夹。
2. 点击「开始扫描」。程序先读取本地文件，再显示联网识别的进度。
3. 输入清单名，例如「生存服」，点击「保存到清单」。重复扫描会更新已有模组的文件名、指纹和版本，保留手动映射、备注和忽略状态。

扫描只读取选定目录的顶层文件。禁用文件、损坏的 jar 和子目录会在结果中提示。联网识别超时时，可保存已经完成的本地结果。没有获得平台匹配的模组需要手动核对。

也可以通过「清单 → 管理模组清单… → 从JSON导入清单」导入由 modcheck 导出的清单。

## 3. 检查兼容性

1. 在主窗口选择清单、目标游戏版本和加载器。
2. 点击「开始检查」。较早的正式版可通过目标版本列表里的「自定义…」输入。
3. 按状态筛选。将鼠标移到模组名或版本上，可查看判定原因和可用版本。
4. 需要分享报告时，点击「导出 JSON」。

检查使用了缓存时，进度条下方会显示命中次数。点击「立即联网重查」可对当前条件重新获取数据。「设置」中可以关闭兼容性检查读取缓存。

| 状态 | 含义 |
| --- | --- |
| 就绪 | 最新的适用正式版支持目标版本 |
| 需注意 | 有较早的适用正式版，可先使用该版本 |
| 仅存测试版 | 仅查到支持目标版本的 Alpha 或 Beta |
| 阻塞 | 查到的适用版本都无法支持该目标 |
| 未判定 | 缺少平台匹配，或查询失败，需进一步确认 |
| 已忽略 | 此条目已被手动排除 |

### 怎么读状态与版本列

- 版本列的箭头左边是你的当前模组版本。程序从文件指纹或 jar 内信息读取它。读取不到时显示「—」。
- 「仅存测试版」表示只有测试通道支持目标。确认可接受风险后再用，并先备份存档。
- 「阻塞」的详情会显示没有目标加载器、没有目标游戏版本或项目缺少文件等原因。
- 「未判定」可在详情里查看超时、限流或匹配失败的原因。需要手动匹配时，见第 5 节。

## 4. 下载建议版本

完成检查后点击「下载建议版本…」，选择保存目录。默认提供「就绪」和「需注意」里的建议版本。可以勾选测试版。

点击「开始下载」后，遇到同名文件会显示已有文件和待下载构建的信息，可选择跳过或覆盖。同批多个构建重名时，每个文件名可以选择一个构建。下载完成后可查看失败原因。

下载只写入所选目录。选择当前使用的 mods 目录时，程序会要求确认。

- 下载可用的主 jar。一个可下载的 jar 都没有时，该条目会列为跳过。
- 点击「取消」会停止剩余下载，已下载完成的文件会保留。
- 下载完成后，在服务端替换同一模组的旧版本，避免同时留下两个版本。操作前请备份存档与原来的 mods 目录，重启后检查服务端日志。

## 5. 管理清单

通过「清单 → 管理模组清单…」创建、重命名、删除、导出或导入清单。选中左边的清单，再选右边的模组，即可切换忽略状态、删除记录，或填写 Modrinth 项目链接或 slug。指定项目需通过联网验证才会保存。将鼠标移到文件名上可查看 Forge 或 NeoForge 文件中声明的模组 ID。

每次修改会立即保存。清单文件在配置目录下的 `profiles` 子目录中，每个清单对应一个 JSON 文件。删除清单需输入完整清单名确认。导出的 JSON 清单可再次导入。

## 6. 常见问题

- **选不到清单**。先保存一次扫描结果或导入一份 JSON 清单，再回主窗口的下拉框选择。
- **游戏版本读取失败**。可输入正式版号，也可在「设置 → 重新加载游戏版本」重试。
- **联网识别超时**。可保存本地扫描结果，之后重扫同一目录，或为未匹配条目手动指定平台项目。
- **HTTPS 证书验证失败**。查看出错域名和证书提示，检查系统时间及代理所用的系统证书。下载走 Modrinth CDN，查询走 API，两个地址的网络情况可能不同。
- **需要代理**。在「设置」里填入可用的 HTTP 代理，例如 `http://127.0.0.1:7890`。
- **切换深浅色**。在「设置 → 外观」中选择跟随系统、浅色或深色，保存后立即生效。
- **配置目录正在使用**。同一配置目录只允许一个写入实例。关闭已运行的 modcheck，或用不同的配置目录另开实例。

## 7. 术语表

| 术语 | 含义 |
|---|---|
| 模组 | 放进 mods 文件夹、由服务端加载器加载的 `.jar` 文件 |
| 模组清单 / 清单 | 本工具记录「你有哪些模组」的文件，一份清单就是一个 JSON 文件；检查以清单为单位 |
| 服务端加载器 | Fabric / NeoForge / Forge 之一，必须与你服务端实际使用的一致 |
| 官方正式版 | Mojang 发布的正式版本（例如 `26.3`）；快照版本（例如 `26.4-snapshot-2`）不在支持范围 |
| 快照 / 测试版 | 快照是游戏的 snapshot 版本。模组测试版指 beta 或 alpha 通道，需要勾选才会下载 |
| 主文件 | Modrinth 为某个版本提供的主要下载文件（通常是一个 `.jar`）；源码包、文档包不算 |
| 文件指纹 | jar 文件的 sha1，用来向 Modrinth 反查「这是哪个项目的哪个版本」 |
| 完全同名 | 名字规范化后与平台项目名完全相等。本工具只认完全同名，不做相似匹配 |
| 平台项目 | 模组在 Modrinth 上的项目，用 slug 表示（例如 `carpet`） |
| slug | 平台项目的短标识，例如 `carpet`、`journeymap`；项目链接 `https://modrinth.com/mod/carpet` 里的最后一段就是它 |
| 识别来源 | 某个模组的身份是怎么确定的：文件指纹 / jar 内信息 / 名称搜索 / 文件名猜测 |
