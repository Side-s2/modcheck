# modcheck 使用教程

> 面向第一次使用本工具的服主与玩家。本教程按程序的真实界面编写，每一步都说明「做完之后你应该看到什么」，便于自查是否走对。
> 适用范围：命令行版（`modcheck` / `modcheck.exe`）与图形界面版（`modcheck-gui.exe`）。两者的判定逻辑完全相同。

## 快速开始（三分钟上手）

如果你已经装好本工具、只想尽快跑通一次，照下面五步做即可。每步后面的「→」是做完应当看到的结果，可以对照自查。

1. **找到你的 mods 文件夹** —— 服务端通常在根目录，例如 `C:\servers\survival\mods`
   → 一个装着若干 `.jar` 的文件夹，本工具不会修改它
2. **建立清单** —— 图形界面用「清单 → 扫描 mods 文件夹…」；命令行选主菜单 `[2]`
   → 进度走完后提示「正在联网识别」，稍候提示识别出 N 个模组
3. **给清单起个自己认得的名字并保存**（例如「生存服」）
   → 提示清单已保存，并给出模组总数
4. **做一次检查** —— 选好清单、目标版本（如 `26.3`）、加载器（通常是 Fabric），点「开始检查」
   → 进度逐个模组推进，结束后出现一条结论横幅
5. **看结论并处理** —— 🟢 不用管；🟡 与 🟠 需你决定；🔴 必须先解决；⚪ 是没查到、不算失败
   → 分页签列出各状态模组，点某一行可在下方看详情与建议

到这里就已经会用了。需要下载可用版本、修改清单或排查问题时，再看后面的对应章节。

## 1. 这个工具做什么、不做什么

**它做的事**：在把 Minecraft 服务端升级到新版本之前，检查你 mods 文件夹里的模组是否都已经支持「目标游戏版本 + 目标服务端加载器」，并把结论分成六种状态，逐条给出原因与建议。

**它不做的事**（这些边界很重要，避免产生错误期待）：

- **不修改你的 mods 文件夹**。检查与扫描都是只读的。下载功能只会往你指定的文件夹里写文件。
- **不安装模组、不改 `server.properties`、不部署到服务端**。下载完成后，把文件复制到 mods 文件夹这一步由你自己完成。
- **不做依赖检查**。缺少前置模组（例如 Fabric API、Architectury）不会被提示。
- **不检查快照版本**。只接受官方正式版（例如 `26.3`），不接受 `26.4-snapshot-2` 这类快照号。
- **不做 CurseForge**。界面固定显示「CurseForge 未启用（缺少 API Key）」。只发布在 CurseForge 上的模组会落到 ⚪ 未判定，而不是被判成阻塞。
- **不做版本模糊匹配**。找不到完全同名的项目时记为 ⚪ 未判定，绝不猜测。

### 六种状态（术语，全书统一）

| 状态 | 含义 | 你通常要做什么 |
|---|---|---|
| 🟢 就绪 | 该加载器的最新正式版就支持目标版本 | 无需处理 |
| 🟠 仅存测试版 | 只有测试版（beta / alpha）支持目标版本 | 不想用测试版就等正式版；想用先备份存档 |
| 🟡 需注意 | 最新正式版不支持，但有一个更早的稳定版可用 | 换成报告「可用：」那一行的版本；若你本地已经是该版本，无需处理 |
| 🔴 阻塞 | 目标版本 + 目标加载器下没有任何可用版本 | 按报告的原因与建议处理：等作者更新、换加载器、或在升级前移除该模组 |
| ⚪ 未判定 | 这次没能查到结果（不算失败） | 稍后重跑；仍不行时手动指定平台项目 |
| ⚫ 已忽略 | 你把它标记为忽略，不再判定也不计入统计 | 需要恢复时见第 8 节 |

**完成后你应该看到**：读完本节，你能说出这六种状态里哪些需要你动手（🟠 🟡 🔴 ⚪ 需要你判断或处理，🟢 不需要，⚫ 是你自己关掉的）。

## 2. 开始之前：需要准备什么

开始之前请准备好四项信息。

### 2.1 mods 文件夹的完整路径

通常在服务端根目录下，与 `server.jar` 同级，例如 `C:\servers\survival\mods`。

找不到时，可以这样确认：

- 查看启动脚本（`.bat` / `.sh`）：里面有 `-jar`、`nogui` 之类的行，脚本所在目录一般就是服务端根目录。
- 查看服务端根目录下有没有名为 `mods` 的文件夹。
- 客户端整合包的模组在 `.minecraft\mods`，位置形如 `C:\Users\你的用户名\AppData\Roaming\.minecraft\mods`。请注意：本工具检查的是**服务端实际加载的**模组。

### 2.2 目标游戏版本

必须是官方正式版号，例如 `26.3`、`1.21.4`。不知道填什么时，运行 `modcheck versions --limit 10` 查看最近的正式版列表，或看图形界面「目标版本」下拉里的候选项。

### 2.3 服务端加载器

只能是 Fabric、NeoForge、Forge 之一，必须与你服务端实际使用的一致。判断方法：

- mods 文件夹里的 jar 文件名通常带加载器后缀，例如 `-fabric`、`-neoforge`、`-forge`。
- 服务端根目录的文件也能看出线索，例如 `fabric-server-launch.jar`（Fabric）、`user_jvm_args.txt` 与 `libraries` 目录（NeoForge / Forge 常见）。
- 服务端启动日志开头会写明加载器与版本。

选错加载器的后果是大量模组被判为 🔴 阻塞，原因行会写「该模组没有 X 版本」。这本身也是有价值的信息：它直接告诉你换加载器要付出多大代价。

### 2.4 能访问 Modrinth 与 Mojang 版本清单的网络

程序要联网访问两个数据源：Modrinth（模组数据）与 Mojang 官方版本清单（游戏版本列表）。国内网络环境可能需要代理，设置方法见第 9.4 节。

### 2.5 选择入口

- **不想记命令**：用图形界面版，见第 10 节的对照表。
- **要写脚本、要在服务器上远程操作**：用命令行版。

**完成后你应该看到**：你能写下这四项——mods 文件夹路径、目标版本号、加载器名称、是否需要代理。四项缺一，后面的步骤都会卡住。

## 3. 第一次运行

### 3.1 打包版（推荐）

1. 把整个发布文件夹解压到任意位置。**不要只单独拷贝 `modcheck.exe`** —— 它需要同目录下的 `.dll` / `.pyd` 文件。
2. 命令行版：双击 `modcheck.exe`（或目录里的 `启动CLI.cmd`）。
   图形界面版：双击 `modcheck-gui.exe`（或目录里的 `启动GUI.cmd`）。
3. 命令行版不带参数启动会进入中文菜单；图形界面版会打开主窗口。

### 3.2 第一次运行你会看到什么

命令行版的启动横幅与主菜单：

```
=== Minecraft 模组版本检查工具 v0.1.0 ===
配置目录：D:\modcheck\config
数据源：Modrinth 已启用  ｜  CurseForge 未启用（缺少 API Key）

还没有任何模组清单。先选 [2] 扫描你的 mods 文件夹（通常在 服务端根目录\mods）。

[1] 检查模组兼容性
[2] 扫描 mods 文件夹建立清单
[3] 管理模组清单
[4] 设置                    （默认版本、加载器、代理、颜色、并发、缓存）
[5] 检查并下载模组        （检查完可以直接把可用的版本下下来）
[6] 查看官方游戏版本列表
[0] 退出
请选择 > 
```

图形界面版的主窗口：

- 顶部卡片有三项下拉与一个按钮：**模组清单**、**目标版本**、**服务端加载器**、**开始检查**。
- 中间是结论条，然后是状态分页签与结果表格，底部在选中某一行时显示详情（原因 / 可用）。
- 底部按钮：**下载建议版本…**、**导出 JSON**、**导出 Markdown**、**复制重跑命令**。
- 菜单栏：**清单**（扫描 mods 文件夹… / 管理模组清单… / 刷新清单列表）、**设置**（打开设置…）、**帮助**（关于）。

三条需要知道的事实：

1. **配置目录**：所有清单、设置与缓存都放在配置目录里。程序优先使用「程序所在目录`config`」（绿色便携，整个文件夹可以拷走）；该目录不可写时自动改用用户目录（Windows 为 `%APPDATA%\modcheck`），命令行版会在启动时打印一行提示。命令行版可用 `--config-dir` 指定目录，图形界面版也支持 `--config-dir`。
2. **「CurseForge 未启用（缺少 API Key）」是正常状态**，不是错误，也不影响使用。
3. **还没有清单时**：命令行版会提示先选 [2]；图形界面版的「开始检查」按钮不可用，结论条上的提示写的是命令行做法 —— 用菜单「清单 → 扫描 mods 文件夹…」同样可以建立清单（见第 4 节）。

**完成后你应该看到**：命令行版停在第 3.2 节所示的主菜单；图形界面版主窗口正常打开且「开始检查」可达（有清单时）或提示先建立清单（无清单时）。

## 4. 建立清单：扫描 mods 文件夹

**为什么需要清单**：检查是按清单进行的，不是每次都去读文件夹。清单是一份 JSON 文件，记录每个模组的名字、模组 ID、对应的平台项目、识别方式与本地版本。清单可以反复使用，也可以手工增删改（第 8 节）。

### 4.1 扫描操作

命令行版（菜单）：

1. 主菜单选 **[2] 扫描 mods 文件夹建立清单**。
2. 程序提示输入要扫描的文件夹（默认不递归子文件夹）。输入 `C:\servers\survival\mods` 并回车。菜单一次只接受一个文件夹；要一次扫描多个文件夹，请用 4.1 节后面的命令行写法。
3. 程序提示输入清单名（直接回车则使用默认名 `demo`）。建议取一个能认出来的名字，例如 `服务器A`。

命令行版（命令）：

```bat
modcheck scan "C:\servers\survival\mods" --profile 服务器A
```

- 一次给多个文件夹也可以，例如主服与客户端各一份：`modcheck scan "D:\srv\mods" "D:\cli\mods" --profile 服务器A`
- 加 `--new` 表示不合并已有内容，整份替换。

图形界面版：

1. 菜单「**清单 → 扫描 mods 文件夹…**」。
2. 点「**添加文件夹…**」选一个或多个 mods 文件夹（右侧「移除所选」可以删掉选错的）。
3. 在「**存入清单**」里填清单名（默认 `服务器A`）。
4. 点「**开始扫描**」。扫描在后台运行，按钮会变成「取消」。
5. 扫描完成后点「**保存到清单**」。

### 4.2 扫描分两个阶段（这一点必须知道）

**阶段一（本地，有进度）**：程序逐个打开 jar，读取内部元数据（`fabric.mod.json` 等），并计算文件指纹（sha1）。

- 命令行版显示形如 `[████████░░░░░░░░░░░░] 12/30  xxx.jar` 的进度行。
- 图形界面版显示「正在读取 12/30：xxx.jar」。

**阶段二（联网，进度条走满之后才开始）**：**进度条走满不等于扫描结束**。程序还要用文件指纹向 Modrinth 反查，并对还没认出来的模组逐个做名称搜索。

- 这一段是逐个出网的，几十个模组可能要几分钟。
- 图形界面版会显示「正在联网识别还没认出来的模组……（这一步要逐个搜索，可能要一会儿；可以点「取消」中止）」。
- 命令行版在这一段没有逐条进度，看起来像是在等待，请耐心等待，不要重复启动。
- **中途取消或中断**：结果视为不完整，**不会被保存**（图形界面版会显示「⚠ 已取消，结果不完整，不能保存」）。重新扫描即可，已经算过的指纹有缓存，第二次更快。
- **断网时**：程序仍会生成清单，只使用 jar 内信息识别，并提示「⚠ 连不上 Modrinth，本次只用 jar 内信息识别（不影响生成清单，但识别率会低一些）」。

### 4.3 扫描会跳过哪些文件

以下内容不会进入清单，但**每一条都会在输出里列出来**：

- 以 `.disabled`、`.old`、`.bak`、`.off` 结尾的文件：按约定视为已禁用或备份，跳过。想让程序检查它，请去掉后缀。
- 不是 jar 的文件（例如 `README.txt`）。
- 损坏的 jar（无法作为 zip 打开）。如果它本来是个模组，请重新下载该 jar 后再扫描。
- **子文件夹**：不展开（游戏也不会加载 mods 目录下的子文件夹），并提示「发现 N 个子文件夹未扫描」。

### 4.4 扫描完成后你应该看到

命令行版：

```
正在扫描：C:\servers\survival\mods
  ✓ 读到 118 个 jar 文件
  ⚠ 跳过 4 个：
      plugin-old.jar.disabled  已禁用的文件（按约定跳过；想检查请去掉 .disabled 后缀）
      README.txt               不是 jar 文件
      …… （其余 2 个同样逐条列出）
识别结果：
  ✓ 用 Modrinth 文件指纹精确识别：112 个（同时知道了你装的版本号）
  ✓ 用 jar 内元数据识别：3 个
  ✓ 用名称搜索匹配：3 个
清单「服务器A」已更新：新增 115 个，合并 3 个，跳过 4 个，共 118 个模组
文件：D:\modcheck\config\profiles\服务器A.json
```

图形界面版会显示「扫描完成：识别出 118 个模组（指纹 112 / jar 信息 3 / 名称搜索 3），跳过 4 个文件」，点「保存到清单」后弹出「清单「服务器A」已更新：新增 115 个，合并 3 个，共 118 个模组」。

**必须留意的一条告警**：同一个模组存在多个 jar 文件（同一个 modid，例如同时放了 `fabric-carpet-26.1.jar` 与 `fabric-carpet-26.3.jar`）。程序会把它们合并成一条记录，并**显式告警**：

```
⚠️  有 1 个模组存在多个 jar 文件（同一 modid），这可能导致服务器启动失败：
      carpet：保留 [地毯] fabric-carpet-26.3+v260915.jar
              另有一个 fabric-carpet-26.1+v260402.jar —— 建议手工删除多余的那个
```

请按提示手工删除多余的那个 jar。这是会让服务器启动失败的真实事故，不是提醒而已。

### 4.5 没有 jar、只有一份文件名清单时

如果你的模组 jar 已经不在，手上只有一份文件名清单（每行一个文件名），可以用：

```bat
modcheck scan --from-list 文件名清单.txt --profile 服务器A
```

这种模式下**所有条目都是靠文件名猜的**，报告里 modid 前面会带 `~` 标记，结论仅供参考，请人工核对。补上 jar 文件后重新扫描，可以把这些猜测变成确定结果。

**完成后你应该看到**：命令行版运行 `modcheck profile list` 能列出这份清单与模组数；图形界面版在「模组清单」下拉里能看到「服务器A（118 个模组）」。

**自查**：清单里的模组数应当与你 mods 文件夹里的 jar 数对得上（被跳过的那些不算）。对不上时，回看扫描输出里「跳过」那一段，看看是哪些文件被跳过、为什么。

## 5. 做一次检查

### 5.1 检查操作

命令行版（菜单，最常用）：

1. 主菜单选 **[1] 检查模组兼容性**。
2. 选择要检查的模组清单（编号选择；`[b]` 返回上一步，`[q]` 返回主菜单）。选项上会显示模组数与最后修改时间。要直接指定某个清单文件，可以用命令行参数 `--file <清单文件路径>`。
3. 选择目标游戏版本：程序列出最近 10 个官方正式版供编号选择，`[1]` 是最新正式版；也可以用 `[m]` 手动输入版本号；`[b]` 返回上一步。
4. 选择服务端加载器：`[1]` Fabric、`[2]` NeoForge、`[3]` Forge；`[d]` 或直接回车使用默认（默认值可在设置里改）。
5. 确认页会显示清单、目标版本、加载器、数据源与预计请求数、预计用时。输入 `Y`（或直接回车）开始检查。

命令行版（命令）：

```bat
modcheck check --profile 服务器A --mc 26.3 --loader fabric
```

图形界面版：

1. 在顶部三项下拉里选好**模组清单**、**目标版本**、**服务端加载器**。
2. 点「**开始检查**」。按钮会变成「取消」，检查在后台运行，随时可以取消。

### 5.2 检查期间你会看到什么

命令行版的进度行（每秒刷新）：

```
正在检查 120 个模组……  [#######-------------]  42/120  当前：JourneyMap  已用 39 秒  已发现 2 个阻塞  预计还需约 73 秒
```

终端越窄显示的信息越少；宽度不足 80 列时只显示 `检查中 42/120`。非交互（输出被重定向到文件）时改为每完成 20% 打印一行。

图形界面版显示进度条与「正在检查 42/120：JourneyMap」。

**中断**：命令行版按 Ctrl+C、图形界面版点「取消」，都会立刻停止并输出一份标注「结果不完整」的报告，已完成的判定会保留。命令行版此时退出码为 130。

### 5.3 要等多久

- **首次检查（没有缓存）**：受 Modrinth 限速约束，120~200 个模组通常需要 **1~3 分钟**。
- **第二次检查**：通常几秒。Modrinth 数据默认缓存 6 小时；要强制重新请求，加 `--refresh`。
- 确认页给出的「预计用时」是粗略估算，以进度行为准。

### 5.4 检查期间程序可能停下来问你（仅命令行交互模式）

如果清单里存在没有确定平台项目的模组（扫描时没能认出它是 Modrinth 上的哪个项目），命令行的交互式检查会暂停进度并列出相近项目：

```
⚠️  未找到与「Carpet TIS Addition」完全同名的项目

  Modrinth 上搜索到这些相近的项目：
    [1] Carpet TIS Addition   （carpet-tis-addition）   下载 1,580,317
    ...

  [1-5] 选择对应的项目
  [m]   手动输入项目 slug 或 Modrinth 链接
  [s]   本次跳过（记为「未判定」，不影响其它模组）
  [i]   永久忽略这个模组（以后不再检查它）
  [q]   退出检查（已完成的部分会显示）
请选择 > 
```

选定的结果会写回清单，以后检查不再询问。三点需要注意：

- **非交互模式绝不询问、也绝不猜**：`--yes`、或输入输出被重定向/管道时，这些模组直接记为 ⚪ 未判定，报告末尾给出提示与重跑命令。
- **图形界面版不会弹出这个选择**：这些模组直接记为 ⚪ 未判定。要在图形界面里处理，请用「清单 → 管理模组清单… → 指定平台项目」（见第 8 节）。
- 命令行版另有两个开关：`--resolve` 允许在检查期间对没有平台标识的模组做一次名称搜索（每个模组最多试 2 个候选名，默认不搜）；`--pre` 把测试版（beta / alpha）也算作可用。

### 5.5 检查结束后（可选）导出报告

- 命令行版：在命令里加 `--json` / `--md` / `--csv` 指定导出文件。
  ```bat
  modcheck check --profile 服务器A --mc 26.3 --loader fabric --json report.json --md report.md
  ```
- 图形界面版：底部「**导出 JSON**」「**导出 Markdown**」（CSV 目前只在命令行版提供），以及「**复制重跑命令**」把等价命令复制到剪贴板。
- 导出文件名会自动带清单名、目标版本与时间；导出内容永远是完整的，不受 `--quiet` 影响。

**完成后你应该看到**：一份完整的检查报告（报告头 + 结论行 + 分组 + 汇总行 + 下一步）。下一节说明怎么读它。

## 6. 看懂报告：六种状态

### 6.1 报告的结构（从上到下）

1. **报告头**：模组清单与总数、目标版本、服务端加载器、数据源、**识别来源**、检查时间与用时、请求次数与缓存命中次数。
2. **结论行**：一句话回答「现在能不能升级」。
3. **分组**：固定顺序 🔴 阻塞 → 🟠 仅存测试版 → 🟡 需注意 → ⚪ 未判定 → 🟢 就绪 → ⚫ 已忽略。空的分组不打印标题。每个组标题后面跟一句该组的含义。
4. **每条的详情行**：原因（为什么是这个结论）、可用（能用的是哪个版本）、建议（你该做什么）。
5. **说明段**：当有条目的身份是靠文件名猜出来的时候，提醒人工核对。
6. **汇总行**：例如
   `汇总：共 13 个模组，本次检查 12 个  ｜  🟢 就绪 5  ｜  🟠 仅存测试版 0  ｜  🟡 需注意 2  ｜  🔴 阻塞 3  ｜  ⚪ 未判定 2  ｜  ⚫ 已忽略 1`
   「共 13 个」包含已忽略；「本次检查 12 个」不包含已忽略。
7. **下一步**：按实际存在的问题生成的编号清单，里面的命令可以直接复制执行。若没有任何问题项，这一段会替换成「可以开始升级了。升级前记得备份存档和 mods 文件夹。」

### 6.2 六种状态逐条说明

#### 🟢 就绪

- **含义**：你在用的那个加载器的最新正式版，本身就支持目标版本。
- **报告里怎么显示**：原因行形如 `Fabric 最新版 26.3-6.0.9+fabric 已经支持 MC 26.3`；建议行为 `无需处理`。
- **你该做什么**：什么都不用做。
- **一种特殊情况**：偶尔会出现一行提示「`1.11.2 同时提供了 MC 26.1 与其它 MC 版本的构建，下载标着 MC 26.1 的那个`」。这表示同一个版本号有多个 MC 构建，下载或升级时请挑标着你目标版本的那个文件。

#### 🟠 仅存测试版

- **含义**：没有任何正式版支持目标版本，只有测试版（beta / alpha）支持。
- **报告里怎么显示**：原因行形如 `没有任何正式版支持 MC 26.3（Fabric），只有测试版支持`；可用行形如 `可用：31.8.0.49-beta（beta 通道）—— 稳定性自负`；建议行为 `不想用测试版就等正式版；想升级就用这个测试版（记得先备份存档）`。
- **你该做什么**：在服务器上使用测试版有风险。建议等作者发布正式版；确实要用，先备份存档与 mods 文件夹。
- **注意**：这一组**不会被下载**（见第 7 节）。

#### 🟡 需注意

- **含义**：该加载器最新发布的正式版不支持目标版本，但有一个更早的稳定版可用。
- **报告里怎么显示**：原因行会点名「最近发布的那个版本 + 它的日期 + 为什么用不了」（例如只标了某个快照号）；可用行给出版本号与日期；建议行是下面三种之一：
  - `无需处理：你本地就是当前可用的最新版本` —— 你已经在用那个可用版本，什么都不用做。
  - `把 X 换成 Y` —— 把你本地的 X 换成 Y（Y 支持目标版本）。
  - `想换最新版请自行确认是否真的兼容；也可以先用可用的那个版本` —— 报告无法确定你本地装的是哪个版本时给出的提示，需要你自己核对。
- **版本列怎么读**：`5.9.18 → 26.3-6.0.9+fabric` 表示「你当前是 5.9.18，该加载器在目标版本上可用的最新版本是 26.3-6.0.9+fabric」。若你本地就是这个可用版本，版本列只显示一个版本号并注明，不显示箭头。
- **你该做什么**：按报告的「可用」版本升级；改完之后重跑一次检查，确认它变成 🟢。

#### 🔴 阻塞

- **含义**：在目标版本 + 目标加载器下，这个模组没有任何可用版本。**必须先处理**，否则升级后服务器可能无法启动。
- **四种常见原因与对策**：

| 原因行 | 含义 | 对策 |
|---|---|---|
| `该模组没有 Fabric 版本（它只发布了 Forge、NeoForge 版本）` | 作者没有发布你这个加载器的版本 | 改用有版本的加载器（需要更换服务端），或找该模组的替代品 |
| `最高只支持 MC 1.20.1，没有任何支持 26.3 的版本` | 模组没跟上新版本 | 等作者更新；或在升级前先移除它（先备份存档，移除模组可能影响存档内容） |
| `在 Modrinth 上找不到同名项目（可能已删除、改名，或只发布在 CurseForge）` | 找不到这个项目 | 手工去 Modrinth / CurseForge 确认；若它只在 CurseForge 上，本工具暂不支持；若项目已改名，重新扫描可以自动修正 |
| `这个项目在 Modrinth 上没有任何可下载文件（可能已经被作者清空了）` | 项目已废弃 | 确认它是否废弃；如果是，考虑从服务器上移除 |

- **注意**：「最高只支持 MC X」是从该模组最近的版本记录推算出来的近似值，不是绝对结论 —— 作者随时可能发布新版本。
- **网络问题永远不会被判成阻塞**：查不到一律记为 ⚪ 未判定。

#### ⚪ 未判定

- **含义**：这次没能查到结果，报告不对它下结论。它**不是失败**，但会让结论变得不完整。
- **常见原因与对策**：

| 原因行 | 含义 | 对策 |
|---|---|---|
| `查询超时（20 秒无响应），已自动重试 3 次仍然失败` | 网络慢或中断 | 稍后重跑（报告末尾给了可直接复制的命令） |
| `被 Modrinth 限流（请求太频繁），已自动重试仍失败` | 请求太密 | 稍后重跑；仍然频繁时降低并发：`--jobs 2` |
| `Modrinth 服务端出错（HTTP 5xx），不是你的问题，稍后重试即可` | 对方服务故障 | 稍后重跑 |
| `Modrinth 上没有完全同名的项目，本工具不会靠猜来匹配` | 认不出这是哪个项目 | 交互式跑一次逐个确认，或用「指定平台项目」手动指定（第 8 节） |
| `本地 jar 读不了（文件损坏），且没有可用的仓库记录` | 本地 jar 损坏 | 重新下载该 jar，然后重新扫描 |

- 报告中出现 ⚪ 时，结论行会明确写着「本结论不完整」。处理完再用同一个命令重跑一次（缓存命中会很快）。

#### ⚫ 已忽略

- **含义**：你在清单里把这个模组标记为忽略。程序不再判定它，也不把它计入统计（所以汇总行会出现「共 13 个模组，本次检查 12 个」这样的两个数字）。
- **适合**：自己写的模组、只在客户端使用的模组、暂时不想处理的模组。
- **你该做什么**：需要恢复时见第 8 节的「忽略 / 取消忽略」。

### 6.3 报告头上那两行怎么读

**识别来源行**：

```
识别来源：Modrinth 文件指纹 7  ｜  jar 内信息 3  ｜  名称搜索 0  ｜  文件名猜测 3
```

- **文件指纹**：用 jar 的 sha1 向 Modrinth 反查到的项目。最可靠，同时能知道你装的确切版本号。
- **jar 内信息**：从 jar 内部元数据读到的模组标识。
- **名称搜索**：用模组名做精确同名搜索命中的项目。
- **文件名猜测**：只能靠文件名猜出来的。这类条目的 modid 前面会带 `~` 标记，报告末尾会专门说明「请人工核对」。

**关于 `~` 标记**：它描述的是「这个模组的身份是猜的」，与状态无关 —— 一个带 `~` 的条目既可能是 🟢 就绪，也可能是 ⚫ 已忽略。

**关于「当前版本」**：版本列箭头左边是「你当前装的版本」，它只来自可靠来源（文件指纹反查或 jar 内元数据）。两者都没有时显示 `—`。文件名里解析出来的版本号**不用于**这一列。

**完成后你应该看到**：你能对报告里的每一条说出「我要做什么」或「我不用做什么」。如果某一条看不懂，把报告导出（JSON / Markdown）发给维护者，报告里包含了判断所需的全部字段。

## 7. 下载建议的模组版本

### 7.1 什么时候可以用

- **必须先完成一次检查**。下载的内容完全取决于那份报告的内容。
- 命令行版：主菜单 **[5] 检查并下载模组** 会先走一遍与 [1] 相同的检查，检查结束后询问：
  ```
  要不要把可用的版本下载下来？(y/N) > 
      · 只会下载 🟢 就绪（最新版）和 🟡 需注意（可用的旧稳定版）的模组。
      · 🔴 阻塞、🟠 仅存测试版、⚪ 未判定、⚫ 已忽略 一律跳过。
      · 不会动你现在的 mods 文件夹，只会往你选的文件夹里写文件。
  ```
  默认是 `N`（直接回车就是不下载）。
- 图形界面版：底部的「**下载建议版本…**」按钮在检查完成之后才可用；点击后打开「下载建议的模组版本」窗口。
  还没有检查过就点击，程序会提示「下载建议版本需要先有一次检查结果 —— 请先点「开始检查」」。
- **检查被中断时报告是不完整的**：请重新跑一次完整的检查，再下载。

### 7.2 它会下什么、不下什么

| 报告里的状态 | 是否下载 | 下载哪个版本 |
|---|---|---|
| 🟢 就绪 | 下载 | 目标加载器的最新正式版（版本列箭头右边那个） |
| 🟡 需注意 | 下载 | 报告「可用：」那一行的版本（支持目标版本的较早稳定版） |
| 🟠 仅存测试版 | 不下载 | — |
| 🔴 阻塞 | 不下载 | — |
| ⚪ 未判定 | 不下载 | — |
| ⚫ 已忽略 | 不下载 | — |

补充规则：

- **只下载主文件**：Modrinth 标记为 primary 的 `.jar`；没有标记时取第一个 `.jar`。源码包、文档包等附加文件不下载，汇总里会说明有几个模组存在附加文件。
- 某个版本的记录里如果**一个可下载的 `.jar` 都没有**，该模组会被跳过，并在汇总的「跳过」里写明原因。
- **不做依赖解析**：缺少前置模组不会提示（例如 Fabric API 需要你自己确认）。

### 7.3 下载到哪里

- 目标文件夹由你选择。程序**不会**修改你现有的 mods 文件夹，只会往你选的文件夹里写文件。
- **建议新建一个空文件夹**（例如 `D:\modcheck-download`），不要直接选正在使用的 mods 文件夹。
- 如果你选的目录名就是 `mods`（或路径里包含 `.minecraft`），程序会先提醒一次并让你确认；确认后仍然可以下载。
- 目标文件夹不存在时会问你是否创建；写不进去时会让你换一个。磁盘剩余空间可能不够时会先提醒。

### 7.4 同名文件怎么处理（默认不覆盖）

- **命令行版**：开始前逐个询问：
  ```
  ⚠ 已存在同名文件：fabric-carpet-26.3+v260915.jar
     现在这个：1.2 MB，修改于 2026-09-20 21:03
     将要下载：1.5 MB，来自 Modrinth（Carpet 26.3）
     [o] 覆盖它  [s] 跳过这个  [a] 后面的全部覆盖  [k] 后面的全部跳过  [q] 取消下载
  请选择 > 
  ```
  **直接回车 = 跳过**，不会覆盖你已经有的文件。程序会同时显示「现在这个」与「将要下载」的大小与来源，便于判断哪个更新。
- **图形界面版**：同名文件在表格的「覆盖」列显示为复选框 `覆盖已有`，**默认不勾选 = 跳过**；只有你勾选的文件才会被覆盖。窗口上方会说明「将下载 N 个文件，其中 M 个会覆盖已有文件」。
- 被跳过的不算失败，会出现在结果汇总的「跳过 N 个」里。

### 7.5 下载过程

- 命令行版进度行：`正在下载 30 个文件……  [###-------]  9/30  当前：xxx.jar  12.3/45.6 MB  已用 8 秒`
- 图形界面版：进度条与「正在下载 12/30：xxx.jar」。
- 同时下载 3 个文件；每个文件失败最多重试 2 次（间隔 1 秒、2 秒）。
- **可以取消**（命令行按 Ctrl+C、图形界面点「取消」）：已经下载完成的文件会保留，没有下载完的临时文件会被清理。

### 7.6 结果汇总

```
下载完成：30 个文件里 28 个成功、1 个跳过、1 个失败。用时 42 秒，共 156.7 MB。
  ✓ 成功 28 个 → D:\modcheck-download
  ⏭ 跳过 1 个：fabric-carpet-26.1+v260402.jar（你选择了跳过）
  ✗ 失败 1 个：
      lithium-fabric-0.26.2+mc26.3.jar —— 校验失败（文件损坏，已删除），已重试 2 次
提示：把下好的 .jar 复制到服务端的 mods 文件夹，然后重启服务器。
```

失败原因与对策：

| 失败原因 | 含义 | 对策 |
|---|---|---|
| `校验失败（文件损坏，已删除）` | 下载过程中文件损坏，校验不通过 | 再下载一次通常就好；程序已删除坏文件，不会用它覆盖你原有的文件 |
| `写不进去（磁盘满或没有权限）` | 磁盘空间不足或目录不可写 | 换一个文件夹，或清理磁盘空间。这类失败不会反复重试 |
| `下载失败（网络问题或连接中断）` | 网络故障 | 检查网络或代理后重试 |

单个文件失败**不会影响**已经下载成功的文件；全部失败时汇总末尾会追加一句「✗ 一个都没下成功。可以稍后重试；如果是网络问题，先检查代理设置」。

### 7.7 下完放哪

1. **先备份**服务端现有的 mods 文件夹（整份复制一份，出问题可以回退）。
2. 把下载好的 `.jar` 复制到服务端的 mods 文件夹。
3. **同名旧文件要自己删除**：如果旧 jar 与新 jar 的文件名不同（例如版本号变了），两个文件会同时存在于 mods 文件夹，这会让服务器启动失败或行为异常 —— 请删除旧版本的那个 jar。这也是第 4.4 节那条「同一 modid 多个 jar」告警要防的事故。
4. 重启服务器，检查日志开头有没有加载错误。

**完成后你应该看到**：你选的文件夹里出现 `.jar` 文件；汇总行的数字能对上（成功 + 跳过 + 失败 = 本次处理的文件数）；把文件放进 mods 并重启后服务器正常启动。

**注意**：下载功能不下载快照版本、不下载测试版（🟠 一律跳过）、不下载 CurseForge 上的文件、不做断点续传。

## 8. 修改清单

清单可以随时修改。所有修改**只影响清单文件（JSON）**，不会动你 mods 文件夹里的任何 jar 文件。

### 8.1 入口

命令行版：主菜单 **[3] 管理模组清单** → 在清单列表屏选择一份清单 → 进入该清单的管理屏：

```
=== 管理清单「服务器A」（120 个模组）===
  [1] 查看模组列表
  [2] 删除模组
  [3] 指定平台项目（手动匹配）
  [4] 忽略 / 取消忽略模组
  [r] 重命名这个清单
  [d] 删除这个清单
  [b] 返回清单列表
  [q] 返回主菜单
```

图形界面版：菜单「**清单 → 管理模组清单…**」。窗口左侧是清单列表（下方有「新建空清单」「重命名清单」「删除清单」），右侧是所选清单的模组表格（模组 / 平台标识 / 状态），下方三个按钮：「忽略 / 取消忽略」「指定平台项目」「删除模组」。所有改动立即写盘。

### 8.2 删除模组（[2] / 「删除模组」）

- **作用**：把某个模组从清单里移除，检查时不再出现。
- **怎么定位**：编号（多个用逗号分隔，例如 `3,7,12`）、模组名、modid 或文件名都可以。
- 命令行版会二次确认，并明确说明「这只会从清单记录里删掉它们：不会删除你 mods 文件夹里的 jar 文件」。
- **想让它回来**：重新扫描 mods 文件夹即可。
- **完成后你应该看到**：`✓ 已删除 N 个模组，清单「服务器A」现在有 M 个模组`；图形界面版表格立刻少一行。

### 8.3 忽略 / 取消忽略（[4] / 「忽略 / 取消忽略」）

- **忽略**：以后检查不再判定它，也不计入统计，报告里出现在 ⚫ 已忽略组。适合自己写的模组、只用于客户端的模组。
- **取消忽略**：恢复正常判定（有平台标识的恢复为手动指定，没有的恢复为未匹配）。
- **操作路径（重要）**：取消忽略请在**命令行版**的「管理清单 → [4] 忽略 / 取消忽略模组 → 选 [2] 取消忽略」里操作。
  当前版本的图形界面里，这个按钮只执行「忽略」（表格的状态列也固定显示「参与检查」），不能用来恢复。
- 也可以在检查期间弹出的匹配提示里按 `[i]` 永久忽略某个模组。
- **完成后你应该看到**：`✓ 已忽略「OldStuff」。以后检查不再判定它；列表里会显示在 ⚫ 已忽略组。` 或 `✓ 已取消忽略「OldStuff」，下次检查会正常判定它。`

### 8.4 指定平台项目（[3] / 「指定平台项目」）

- **作用**：告诉程序「这个模组对应 Modrinth 上的哪个项目」。用于解决两种情况：报告里是 ⚪ 且原因为「Modrinth 上没有完全同名的项目」；清单里某个模组的「来源」是空的。
- **输入内容**：Modrinth 的项目 slug（例如 `carpet`）或完整链接（`https://modrinth.com/mod/carpet`）。
- **定位方式**：编号 / 模组名 / modid / 文件名。
- 程序会**联网校验**这个项目是否存在：找不到会提示检查拼写或直接粘贴链接；连不上 Modrinth 会明确告诉你「清单没有改动」。
- 成功后这个模组被记为「手动指定」，下次检查直接用它，不再询问。
- **完成后你应该看到**：`✓ 已把「Carpet TIS Addition」指定为 Modrinth 项目「Carpet TIS Addition」（carpet-tis-addition）。下次检查直接用这个项目，不再询问。`；重新检查后该模组不再出现在 ⚪ 里。

### 8.5 重命名清单（[r] / 「重命名清单」）

- 清单名不能包含 `` \ / : * ? " < > | `` 这些字符。
- 清单文件名与清单内的名字会一起改。重名会被拒绝（绝不覆盖已有清单）。
- 重命名成功后管理屏会切换到新名字继续管理。
- **完成后你应该看到**：`✓ 清单「服务器A」已重命名为「主服」。文件也已经改名。`

### 8.6 删除这个清单（[d] / 「删除清单」）

- **这是唯一不可撤销的操作**：清单文件会被直接删除，里面记录的中文名、备注、手动指定的平台项目都会一起消失。
- 命令行版要求你**完整输入清单名**才会执行；图形界面版同样要求输入清单名确认。
- **不会删除** mods 文件夹里的任何 jar 文件。
- 确认之前可以先复制一份清单文件作为备份：它在配置目录的 `profiles` 子目录下，文件名是 `<清单名>.json`。
- **完成后你应该看到**：`✓ 清单「服务器A」已删除。还剩 N 个清单。`

### 8.7 新建空清单（[n] / 「新建空清单」）

建立一份 0 个模组的清单，之后可以扫描把内容填进去。

### 8.8 清单文件在哪里

- 配置目录下的 `profiles` 子目录，一份清单一个 JSON 文件（例如 `D:\modcheck\config\profiles\服务器A.json`）。
- 命令行版 `modcheck profile show 服务器A` 以表格显示内容；加 `--json` 输出完整 JSON。
- 可以直接用文本编辑器查看；手工编辑时请保持 JSON 合法（多一个或少一个逗号会导致清单读不了）。

**完成后你应该看到**：管理屏或对话框里的模组数与状态立刻变化；命令行版 `modcheck profile list` 显示新的模组数；下一次检查反映这些改动。

## 9. 出问题了怎么办

### 9.1 连不上网：报告全是 ⚪，退出码 4

你会看到：

```
✗ 连不上 Modrinth（网络不可用或需要代理）。
  请检查网络，或设置代理：modcheck config set proxy http://127.0.0.1:7890
  本次没有检查任何模组。
```

判断依据是：本次检查确实发出过请求，但一次都没有成功，且没有任何模组得出结论。对策：检查网络；需要代理时按第 9.4 节设置；然后重跑。

### 9.2 有些模组是 ⚪ 未判定

这不是失败，而是「没查到」。按顺序处理：

1. **原样重跑一次**。多数超时与限流是临时的；缓存命中后很快。
   ```bat
   modcheck check --profile 服务器A --mc 26.3 --loader fabric --refresh
   ```
2. **原因行是「Modrinth 上没有完全同名的项目」**：用交互模式跑一次逐个确认，或在管理清单里「指定平台项目」（第 8.4 节）。
3. **原因是限流**：降低并发再跑（`--jobs 2`），或等几分钟。
4. **原因是「本地 jar 读不了」**：重新下载该 jar，然后重新扫描。
5. **确认不掉的条目**：它只会让结论标上「不完整」，**不会被当成不兼容**，不会导致误判为阻塞。

### 9.3 下载失败

见第 7.6 节的表。三条要点：

- 校验失败的文件已被删除，不会覆盖你原有的文件，重下一次通常就好。
- 写不进去（磁盘满或没有权限）重试无用，请换目录或清理空间。
- 一个文件失败不影响已经下载成功的文件。

### 9.4 想换代理（国内网络）

- 命令行版（立即生效并写入配置文件）：
  ```bat
  modcheck config set proxy http://127.0.0.1:7890
  ```
  清除代理：`modcheck config set proxy null`（`null`、`none`、`-` 都表示清除）。查看当前设置：`modcheck config show`。
- 图形界面版：菜单「**设置 → 打开设置…**」，在「代理」一栏填写（例如 `http://127.0.0.1:7890`；填 `null` / `none` / `-` 表示清除），保存。
- 地址格式不合法时程序会拒绝并说明正确写法，不会把坏值写进配置。
- **已知限制**：代理不可用时，每个请求会重试 3 次并指数退避，因此 200 个模组的清单可能要等几分钟才给出结论（结论本身是正确的：退出码 4 加上第 9.1 节的提示）。

### 9.5 其它常见情况

| 你会看到 | 含义 | 对策 |
|---|---|---|
| `✗ 无法识别的游戏版本：「abc」` | 版本号格式不对 | 用 `26.3`、`1.21.4` 这样的正式版号；`modcheck versions` 查看列表 |
| `✗ 「26.4-snapshot-2」是快照版本，本工具只检查官方正式版` | 填了快照号 | 换成正式版号，或等它转正 |
| `✗ 官方版本列表里没有「26.9」` | 这个版本号不存在 | 用 `modcheck versions` 查看最近的正式版 |
| `✗ 暂不支持加载器「quilt」` | 加载器不在支持范围 | 只能选 fabric / neoforge / forge |
| `✗ 没有名为「服务器B」的清单。可用的清单：服务器A` | 清单名写错 | 使用列出的名称，或用 `modcheck profile list` 查看 |
| `✗ 清单文件读不了：...` | 清单 JSON 损坏（常见原因是手工编辑时少了逗号） | 先看其它清单是否正常；修好后重试，或从备份恢复 |
| `⚠ 配置目录不可写：... 已自动改用：...` | 程序目录在受保护位置（例如 Program Files） | 无需处理；也可以用 `--config-dir` 指定一个可写目录 |
| `⚠ 缓存目录不可写，本次检查将不使用本地缓存（速度会慢一些）` | 缓存写不进去 | 无需处理，只是会慢一些 |
| 检查中按了 Ctrl+C | 结果不完整 | 已完成的结论仍然有效；退出码 130；重跑即可（缓存命中很快） |
| `⚠️ 本次有 N 个模组因被 Modrinth 限流而未能判定；结果可能不完整，建议稍后重跑一次` | 请求太密 | 稍后重跑，或加 `--jobs 2` |
| 中文显示成乱码 | 终端编码问题 | 程序启动时会自动尝试把终端切到 UTF-8；若仍异常，先执行 `chcp 65001`，或设置环境变量 `PYTHONIOENCODING=utf-8` |
| 图形界面「目标版本」下拉是「（无）」 | 没取到官方版本列表（通常是网络问题） | 检查网络或代理后重新打开程序 |

### 9.6 想确认版本号、缓存或设置

```bat
modcheck versions --limit 10     :: 官方正式版列表
modcheck config show             :: 当前设置（默认版本、加载器、代理、并发、缓存）
modcheck cache info              :: 缓存文件数与体积
modcheck cache clear             :: 清理缓存（下次会重新联网请求）
modcheck cache clear --older-than 7d   :: 只清理 7 天前的缓存
```

## 10. 命令行与图形界面：怎么选

两者是同一个程序的两个前端：**判定逻辑完全相同**，使用同一份配置与清单，可以随时换着用。

| | 命令行版（modcheck / modcheck.exe） | 图形界面版（modcheck-gui.exe） |
|---|---|---|
| 面向 | 习惯终端、要轻量、要写脚本 | 想少打命令、要一目了然 |
| 体积 | 约 7 MB | 明显更大（Qt 界面框架的固有成本） |
| 第三方依赖 | 零 | 需要 PyQt6 / Qt6（打包版已包含） |
| 检查与结果分组 | 有 | 有（分页签按状态筛选，选中行看详情） |
| 扫描 mods 文件夹 | 有 | 有 |
| 管理清单 | 有 | 有 |
| 设置（含代理） | 有 | 有 |
| 下载建议版本 | 有（菜单 [5]，检查后询问） | 有（检查后点「下载建议版本…」） |
| 导出 | JSON / Markdown / CSV | JSON / Markdown |
| 找不到项目时弹候选让你选 | 有（仅在交互式终端里） | 无：这些模组记为 ⚪ 未判定，改用「指定平台项目」 |
| 适合写脚本 / 自动化 | 适合（子命令 + 退出码） | 不适合 |

**数据互通的依据**：两者的清单、设置与缓存都放在同一个配置目录里（程序目录下的 `config`，不可写时回退到 `%APPDATA%\modcheck`）。在图形界面里建立的清单，命令行版 `modcheck profile list` 立刻能看到；反过来也一样。

**怎么选**：

- 只想在升级前查一次、不想记命令 → 用图形界面版。
- 要写脚本、放进计划任务、在服务器上远程操作 → 用命令行版。
- 两个都装也可以，它们互不干扰（但不要同时运行，两者会读写同一份配置与缓存）。

**图形界面版的两个使用要点**：

1. 还没有任何清单时，「开始检查」按钮不可用，界面上的提示文字写的是命令行做法。请用菜单「**清单 → 扫描 mods 文件夹…**」建立清单（第 4 节）。
2. 「目标版本」下拉里如果显示「（无）」，说明没有取到官方版本列表（通常是网络问题）。检查网络或代理后重新打开程序。

## 11. 常用命令、参数与退出码速查

打包版用户请把下面的 `modcheck` 换成 exe 目录下的 `modcheck.exe`。

```bat
:: 建立或更新清单（读 jar 内元数据 + 文件指纹反查 Modrinth）
modcheck scan "C:\servers\survival\mods" --profile 服务器A

:: 检查整份清单在目标版本 + 加载器下能不能用
modcheck check --profile 服务器A --mc 26.3 --loader fabric

:: 检查并导出报告
modcheck check --profile 服务器A --mc 26.3 --loader fabric --json report.json --md report.md

:: 忽略缓存，强制重新请求
modcheck check --profile 服务器A --mc 26.3 --loader fabric --refresh

:: 被限流时降低并发
modcheck check --profile 服务器A --mc 26.3 --loader fabric --jobs 2

:: 查看官方正式版列表
modcheck versions --limit 10

:: 查看清单列表 / 某份清单的内容
modcheck profile list
modcheck profile show 服务器A

:: 设置与查看代理
modcheck config set proxy http://127.0.0.1:7890
modcheck config show

:: 缓存
modcheck cache info
modcheck cache clear
```

两个常用变体：

```bat
:: 没有 jar，只有一份文件名清单（全部靠文件名猜，结论需人工核对）
modcheck scan --from-list 文件名清单.txt --profile 服务器A

:: 不建立清单，直接检查一个 mods 文件夹（临时清单，不写盘）
modcheck check --mods-dir "C:\servers\survival\mods" --mc 26.3 --loader fabric
```

`modcheck check` 的其它常用参数（`modcheck check --help` 可看全部）：

| 参数 | 作用 |
|---|---|
| `--quiet` | 不显示进度条，且 🟢 就绪组只显示数量、不列明细（🔴 / 🟠 / 🟡 / ⚪ / ⚫ 仍然逐条列出；导出内容不受影响） |
| `--pre` | 把测试版（beta / alpha）也算作可用 |
| `--resolve` | 对清单里没有平台标识的模组做一次名称搜索（默认不搜，每个模组最多试 2 个候选名） |
| `--yes` | 非交互模式：所有提问一律取默认值（绝不猜测） |
| `--no-color` | 不使用颜色（输出被重定向到文件时会自动关闭颜色） |
| `--debug` | 显示调试信息（排查问题时使用） |
| `--config-dir <目录>` | 指定配置目录 |
| `--window <条数>` | 高级选项：每个项目取多少条版本记录（默认 25，不建议改动） |

**退出码**（写脚本时用）：

| 码 | 含义 |
|---|---|
| 0 | 全部就绪，或只有 🟡 / 🟠（可以升级，后两类需要你自己拍板） |
| 1 | 存在 🔴 阻塞项 |
| 2 | 存在 ⚪ 未判定项，且没有 🔴 阻塞项 |
| 3 | 参数或配置错误（版本号写错、清单损坏、导出失败等） |
| 4 | 数据源整体不可用（连不上 Modrinth） |
| 130 | 被中断（Ctrl+C） |

优先级为 3 > 4 > 130 > 1 > 2 > 0：同时存在阻塞与未判定时返回 1。

## 12. 术语表

| 术语 | 含义 |
|---|---|
| 模组 | 放进 mods 文件夹、由服务端加载器加载的 `.jar` 文件 |
| 模组清单 / 清单 | 本工具记录「你有哪些模组」的文件，一份清单就是一个 JSON 文件；检查以清单为单位 |
| 服务端加载器 | Fabric / NeoForge / Forge 之一，必须与你服务端实际使用的一致 |
| 官方正式版 | Mojang 发布的正式版本（例如 `26.3`）；快照版本（例如 `26.4-snapshot-2`）不在支持范围 |
| 快照 / 测试版 | 快照是 snapshot；测试版专指 beta / alpha 通道。两者都不被下载 |
| 主文件 | Modrinth 为某个版本提供的主要下载文件（通常是一个 `.jar`）；源码包、文档包不算 |
| 文件指纹 | jar 文件的 sha1，用来向 Modrinth 反查「这是哪个项目的哪个版本」 |
| 完全同名 | 名字规范化后与平台项目名完全相等。本工具只认完全同名，不做相似匹配 |
| 平台项目 | 模组在 Modrinth 上的项目，用 slug 表示（例如 `carpet`） |
| slug | 平台项目的短标识，例如 `carpet`、`journeymap`；项目链接 `https://modrinth.com/mod/carpet` 里的最后一段就是它 |
| 识别来源 | 某个模组的身份是怎么确定的：文件指纹 / jar 内信息 / 名称搜索 / 文件名猜测 |
| `~` 标记 | 报告里 modid 前的波浪号，表示这个模组的身份只能靠文件名猜出来，需要人工核对 |
| 未判定 | 没查到的条目（⚪）。不算失败，但会让结论不完整 |
| 已忽略 | 你标记为不再检查的条目（⚫）。不计入本次检查的统计 |
