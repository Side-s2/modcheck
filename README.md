# modcheck —— Minecraft 模组兼容性检查

> 在**升级服务端游戏版本之前**，检查服务器上的模组是否支持目标版本与加载器。

升级 Minecraft 版本最麻烦的不是升级本身，而是**升级完才发现某个模组不支持** —— 服务端起不来，或者起来了但某个功能悄悄失效。
modcheck 把这件事提前：它读你的 mods 文件夹，逐个去 Modrinth 查证，然后告诉你哪些能用、哪些必须处理。

---

## 它给出的结论

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| 🟢 就绪 | 目标版本上有可用版本 | 不用管 |
| 🟡 需注意 | 最新正式版不支持，但**有一个更早的稳定版**可用 | 用那个旧稳定版，别下最新版 |
| 🟠 仅存测试版 | 只有 alpha/beta 支持目标版本 | 自行评估风险，建议先备份存档 |
| 🔴 阻塞 | 目标版本上没有任何可用版本 | 必须先解决，否则无法升级 |
| ⚪ 未判定 | 没查到（**不算失败**） | 可稍后重跑；必要时手动指定平台项目 |
| ⚫ 已忽略 | 你主动标记为不参与检查 | 不参与判定 |

**它不会猜。** 查不到就如实报「未判定」，绝不为了看起来完整而随便选一个版本 ——
一个错误的「就绪」比一个诚实的「未判定」危险得多。

## 下载

从 [GitHub Releases](https://github.com/Side-s2/modcheck/releases) 下载 Windows 图形界面的免安装压缩包。CLI 版本已退役。

## 快速上手

1. 把 `modcheck-*-gui.zip` 解压到**任意一个文件夹**（不要只把 exe 单独拖出来，它需要旁边的文件）。
2. 双击 `启动GUI.cmd`。
3. 菜单栏 **清单 → 扫描 mods 文件夹…**，添加你服务端的 mods 文件夹，点「开始扫描」。
   界面分别显示本地读取和联网识别的进度。联网超时时可保存本地结果。
4. 给清单起个名字（例如「生存服」）并保存。
5. 回到主窗口，选好清单、目标版本、加载器，点 **开始检查**。
6. 用分页签筛选状态，将鼠标移到模组名或版本上可查看判定原因。检查使用缓存时，可点击「立即联网重查」。

需要下载可用版本时，点 **下载建议版本…**。默认下载 🟢🟡 两类的建议版本，可选择包含测试版。遇到同名文件时，会弹窗让你决定跳过或覆盖。

> **所有配置与清单都存在程序同级的 `config` 目录里**，整个文件夹可以随身拷走（绿色便携）。
> 第二次检查会命中缓存，几秒就能出结果。

详细步骤见[使用教程](docs/TUTORIAL.md)。程序内的「帮助 → 使用教程」也可查看。

---

## 它不做的事

- **不修改你的 mods 文件夹**。默认只读；下载必须由你主动触发，且只写入你指定的文件夹。
- **不自动替换或安装模组**。下载下来的文件放在哪、要不要用，由你决定。
- **不重新分发模组文件**。下载的是 Modrinth 官方 CDN 直链。
- 不做快照版本检查、不做依赖递归解析。

## 给开发者

需要 Python 3.11+。源码运行与测试：

```sh
python -m pip install ".[gui,dev]"
python -m modcheck
python -m pytest
```

`gui/` 负责界面，`flows/` 编排扫描、检查、下载和导入导出，`core/` 处理数据和判定规则。流程层通过回调报告进度，测试可以独立运行。
以后新增 Linux 入口时可以直接调用流程层。Linux 上使用系统默认的 Python HTTPS 证书验证，安装引擎无需 Qt。

在 Windows 上构建便携版：

```sh
python -m pip install nuitka
python build/nuitka_build.py --output-dir dist-gui
python build/make_publish.py
```

构建结果位于 `dist-gui/`。修改教程后执行发布脚本，同步程序内帮助和 `publish/` 的副本。
