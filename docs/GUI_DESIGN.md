# GUI 设计规划（一期）

> 状态：**待用户确认** ｜ 目标平台：Windows（Qt 本身跨平台，Linux 未列入一期验收）

## 0. 目标

给同一个人群提供**两种入口**，功能一致、数据互通：

| | CLI 版 | GUI 版 |
|---|---|---|
| 面向 | 习惯终端、要轻量 | 要易用、要好看 |
| 体积 | 约 7 MB | 约 100–150 MB（Qt 的固有成本） |
| 依赖 | **零第三方运行时依赖** | PyQt6 / Qt6 |
| 入口 | `modcheck` | `modcheck-gui` |

**「可拆分」的含义**：两个**独立产物**；CLI 构建时排除 `gui/`，GUI 构建时包含 `core` + `flows` + `gui`。
仓库仍是**同一个** —— 拆成两个仓库会让 `core` 的同步变得痛苦。

## 1. 分层（重构后）

```
core/     纯判定与数据。无 IO、无 print/input、不依赖 cli 或 gui（已有，且有自检脚本守护）
  ↓
flows/    【新增】流程编排：扫描 / 检查 /（三期）下载
          接受 on_progress 回调与 should_stop 取消信号，返回结构化结果，不打印任何东西
  ↓
cli/      只做：解析参数 → 调 flow → 渲染成终端文本
gui/      【新增】只做：Qt 控件 → 调 flow → 更新界面
```

### 为什么必须先做这一步

现状：`cli/commands/` 里**流程与终端输出混在一起**（实测终端 IO 占 10–33% 的行数）。
GUI 若直接调用它，会把终端渲染拖进 GUI；若另写一份流程，**两份逻辑早晚漂移**。

### 重构的验收标准

1. **CLI 的输出逐字不变**（现有测试全绿 + 关键输出做前后对比）；
2. `flows/` 里**不出现** `print` / `console` / `input` / `sys.exit`（用现有的分层自检脚本扩展覆盖）；
3. `core/` **一行都不改**（它已经是干净的）；
4. 扫描与检查都能通过 `should_stop` **真正中途取消**（不是只在循环外判断）。

## 2. GUI 一期范围

**只做「检查 + 结果展示」**，这是 GUI 相对 CLI 价值最大的一块。

### 界面结构


### 关键交互

1. **一键流程**：打开就是上面这个窗口，清单/版本/加载器都有合理默认值，**按一个按钮就能跑**；
2. **不卡界面**：检查在后台线程跑，进度实时更新，**随时可取消**；
3. **结果可筛选**：分页签按状态过滤，颜色与 CLI 完全一致（🔴🟠🟡⚪🟢⚫）；
4. **可导出**：复用现有 `export` 逻辑（JSON / Markdown / CSV）；
5. **菜单栏**：清单管理（二期）、设置、帮助/关于（含许可证与版本）。

### 一期明确不做

- 清单的增删查改 UI（二期 —— 但**已有的 core/profile_ops.py 就是它的后端**）；
- 扫描文件夹的 UI（三期）；
- 下载（三期）；
- 深色模式的**手动**切换（跟随系统即可）。

## 3. 技术方案

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **PyQt6** | 用户指定；项目开源，GPL 合规 |
| 线程 | `QThread` + 信号槽 | Qt 要求 UI 只在主线程；core 的 `ThreadPoolExecutor` 在 worker 里跑，结果用信号回传 |
| 进度/取消 | 复用 `flows` 的 `on_progress` / `should_stop` | **与 CLI 共享同一套机制**，不重复实现 |
| 配置目录 | 与 CLI **共用** | 用户在两个界面之间切换时数据一致 |
| 文案 | 复用 `i18n.py` | 一处改，两处生效 |
| 打包 | Nuitka `--enable-plugin=pyqt6` | 与现有构建脚本同源 |

## 4. 分期

| 期 | 内容 | 交付 |
|---|---|---|
| **0（本次）** | **流程下沉重构** | CLI 行为不变，`flows/` 就位并有测试 |
| **1（本次）** | 检查 + 结果展示 | `modcheck-gui.exe` 可跑通完整检查 |
| 2 | 清单管理 + 设置 UI | 复用 `profile_ops.py` / `settings_ops.py` |
| 3 | 扫描 + 下载 UI | 复用 `flows` 的扫描/下载流程 |

## 5. 风险

| 风险 | 应对 |
|---|---|
| 重构引入回归 | 现有 480+ 测试兜底；关键输出做前后逐字对比 |
| Qt 打包体积/启动慢 | 一期先做 onedir（文件夹版）；单文件版二期再评估 |
| 线程与取消的边界 | 取消必须有测试（跑一半取消，断言不留残状态） |
| 与子代理的工作冲突 | **重构排在子代理完成 A 组之后**，避免同一个文件两处改 |
