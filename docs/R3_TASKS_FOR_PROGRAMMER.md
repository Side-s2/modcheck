## 0. 三条不可破坏的硬约束（先读）

1. **零第三方运行时依赖**：只用标准库。`urllib` 已在 http 层封装好，下载**不要**引 `requests`；进度条**不要**引 `tqdm`。
2. **Windows 与 Linux 双平台**：文件夹选择用 ctypes+COM（Windows）/ 手输（其它平台）；路径一律 `pathlib`；文件名非法字符按平台处理（Windows 才需要替换 `\/:*?"<>|`）。
3. **core / cli 分层（GUI 前瞻）**：新逻辑全部落在 `core/profile_ops.py`、`core/settings_ops.py`、`core/downloader.py` —— **不 print、不 input、不写盘、不直接联网**；`cli/` 只做屏幕与编排。写盘只经 `storage/`。

## 2. 工作 A：交互式清单 / 设置管理（任务 R3-A01 ~ R3-A16）

### R3-A01 ｜ P0 ｜ `core/profile_ops.py`（纯函数）

- **目标**：把「删模组 / 指定平台项目 / 忽略切换 / 新增 / 重命名 / 按标识定位 / 分页」做成**返回新对象**的纯函数。
- **契约**：见 PRD §13.1（`OpResult` / `ResolveResult` / 函数签名）。
- **硬性**：不 import `storage`、不 import `providers`、不写盘、不 print；`resolve_selector` 必须沿用 D33 的全标识匹配顺序（`key → mod_id → sources 各 slug → display_name → cn_name → file_name/aliases`，大小写不敏感）。
- **验收**：
  - `pytest tests/test_profile_ops.py` 全绿；
  - 单测覆盖：命中唯一 / 未命中（返回候选）/ 多命中（ambiguous）/ 删除多个 / 删除后 `updated_at` 变化 / 忽略切换幂等 / 重命名后 `profile.name` 更新 / 分页边界（第 0 页、越界页、空清单）。
- **依赖**：无。

### R3-A02 ｜ P0 ｜ `core/settings_ops.py`（纯函数 + 校验）

- **契约**：见 PRD §13.1。每个 setter 都返回**新的** `Settings`；非法值抛 `ConfigError`（复用 §13.3 的文案 key）。
- **验收**：`tests/test_settings_ops.py`：并发数 1/8 通过、0/9 报错；缓存 TTL 1/168 通过、0/169 报错；代理沿用 D42（`null/none/-/空串` 清除，非法格式拒绝）；`reset_settings()` 等于 `load_settings` 的默认值。
- **依赖**：无。

### R3-A03 ｜ P0 ｜ 清单列表屏 + 管理屏（导航骨架）

- **目标**：`cli/screens_profiles.py`，实现 PRD §13.2 的两屏与所有返回路径。
- **要点**：列表项超过 9 个时要能翻页或输入完整名称（`[m] 输入清单名`）；空清单场景用专门文案；`q` 回主菜单、`b` 回上一层。
- **验收**：注入假输入 `["3","1","b","q"]` 走通"进 [3] → 打开清单 1 → 返回列表 → 回主菜单"，无异常；屏幕输出与 PRD §13.2 逐字一致（golden 文件比对）。
- **依赖**：R3-A01。

### R3-A04 ｜ P0 ｜ 查看模组列表（分页）

- **要点**：每页 20 条；列与 `profile show` 一致（**第二列平台标识保持现状不动**）；`[n]/[p]/[b]`。
- **验收**：30 个模组的清单 → 2 页；`n` 到第 2 页、再 `n` 提示"已经是最后一页了"；`p` 回第 1 页、再 `p` 提示"已经是第一页了"；空清单给专门文案。
- **依赖**：R3-A03。

### R3-A05 ｜ P0 ｜ 删除模组（含二次确认 + 写盘）

- **要点**：支持编号（逗号分隔）与全标识；确认屏**逐条列出**将被删除的模组 + **明确"不会删除 mods 文件夹里的 jar"**；默认 `N`。
- **验收**：
  - 删 2 条 → `✓ 已删除 2 个模组，清单「X」现在有 N-2 个模组。…`；`profile show` 里确实少了 2 条；文件 mtime 变化。
  - 输入 `n` → 清单不变（比对文件字节）。
  - 输入不存在的标识 → 候选建议文案（D33）。
  - 写盘失败（目标目录设只读）→ `✗ 保存失败…` 且**磁盘与内存都不变**。
- **依赖**：R3-A01、R3-A03。

### R3-A06 ｜ P1 ｜ 指定平台项目（手动匹配）

- **要点**：选模组 → 输入 slug/URL → 用 provider 校验存在（`get_project`）→ 写回 `sources.modrinth` + `match_status="manual"`；URL 要能解析出 slug（`https://modrinth.com/mod/carpet` → `carpet`）。
- **验收**：
  - 输入 `carpet` → `✓ 已把「X」指定为 Modrinth 项目「Carpet」（carpet）…`；
  - 输入 `carpet-xyz` → 中文"找不到"文案，清单不变；
  - 断网（代理指向死端口）→ `✗ 现在连不上 Modrinth…（清单没有改动）`，退出码不受影响；
  - 单测：URL 解析表（含 `/mod/`、带查询串、带尾斜杠、纯 slug、非法串）。
- **依赖**：R3-A01、R3-A03、既有 provider。

### R3-A07 ｜ P1 ｜ 忽略 / 取消忽略

## 3. 工作 B：自动下载（任务 R3-B01 ~ R3-B12）

### R3-B01 ｜ P0 ｜ `HttpClient.download`（下载底座）

- **契约**：
  ```python
  def download(self, url: str, dest: Path, *, sha1: str | None = None,
               on_chunk: Callable[[int], None] | None = None,
               timeout: float | None = None) -> int: ...   # 返回字节数
  ```
- **必须做到**：
  1. `limiter.acquire()` **在真正发请求前**调用（与 API 共用同一个限速器）；
  2. 流式写入 `dest.with_name(dest.name + ".part")`，边写边算 sha1，**不把整个文件读进内存**；
  3. 校验通过 → `os.replace(part, dest)`（原子）；校验失败 → 删除 `.part` 并抛 `ProviderVerifyError`（新增领域异常）；
  4. 403/404 → `ProviderHTTPError`；429 → `limiter.pause(…)` 后重试且**不计入业务重试次数**；
  5. 任何异常路径都不得留下 `.part`（用 `try/finally`）。
- **验收**：`tests/test_http_download.py`（假 transport）：正常下载字节一致；sha1 不符 → 抛错 + 无残留文件；中途抛异常 → 无 `.part`；429 → 暂停后成功；`limiter` 调用次数 == 请求次数。
- **依赖**：M1 完成。

### R3-B02 ｜ P0 ｜ `core/downloader.py`：选品与文件名（纯逻辑）

- **契约**：`plan_for` / `conflicts` / `safe_filename`（PRD §14.2）。
- **必须做到**：
  - 只取 🟢 与 🟡；🟡 取 `latest_compat`（"可用"那个），🟢 取 `latest_for_loader`；
  - 只取 **primary** 文件（无 primary 取第一个 `.jar`；没有 `.jar` → 跳过并记原因）；
  - `safe_filename`：空名兜底 `{slug}-{version_number}.jar`；Windows 非法字符替换；长度截断到 200 字符并保留 `.jar` 后缀；
  - `conflicts` 只做"目标目录里是否已有同名文件"的判断，不写盘、不询问。
- **验收**：`tests/test_downloader.py`：给定造的 Report（含 🟢/🟡/🟠/🔴/⚪/⚫ 各一条）→ plan 里只有 🟢/🟡 两条；跳过原因分组正确；文件名边界表（空、非法字符、超长、无 .jar）全过。
- **依赖**：无（可离线）。

### R3-B03 ｜ P0 ｜ `download_all`（并发、重试、取消、进度）

- **必须做到**：
  - 并发 `jobs=3`（`ThreadPoolExecutor`），**每个文件只占 1 个 limiter 名额**；
  - 每文件失败重试 **2** 次（退避 1s/2s），429 不计入重试；
  - `cancel`（`threading.Event`）触发后：停止派发新任务、删除所有 `.part`、已完成的正式文件保留、返回 `cancelled=True`；
  - `on_progress(item, done_bytes, total_bytes)` 由调用方节流；
  - 单个文件失败**不影响**其它文件；返回值汇总 `ok/skipped/failed/bytes_total`。
- **验收**：`tests/test_downloader.py`（假 fetcher，本地文件模拟延迟与失败）：3 并发确实并行（时间断言）；第 2 个文件失败 3 次 → `failed=1`、其余 ok；取消 → 无 `.part` 残留、已完成文件在。
- **依赖**：R3-B02。

### R3-B04 ｜ P0 ｜ CLI 编排：主菜单 [5] + 检查后询问 + 文件夹选择

- **要点**：
  - 主菜单加 `[5] 检查并下载模组`，原 [5] 顺延为 [6]（PRD §14.4）；
  - 走完检查 → 打印报告 → 询问 `要不要把可用的版本下载下来？(y/N)`（默认 **N**）；
  - 文件夹选择：Windows 用 `ctypes` + COM `IFileDialog`（`FOS_PICKFOLDERS`）；失败或非 Windows → 手输；两者都要能在**纯控制台**下工作；
  - 用户取消对话框 → 视为取消下载（回主菜单），**不是错误**。
- **验收**：手工：真机走一遍（选一个空文件夹）；非 Windows/对话框不可用路径用假实现测；取消对话框 → 无任何写盘。
- **依赖**：R3-B01、R3-B03、现有 check 流程。

### R3-B05 ｜ P0 ｜ 同名文件覆盖询问（o/s/a/k/q）

- **要点**：逐个问（默认跳过）；`a`/`k` 之后不再问；`q` 取消整个下载；把结果整理成 `overwrite: Mapping[str, bool]` 传给 `download_all`。
- **验收**：3 个同名文件：逐个 s → 3 个都跳过；选 a → 3 个都覆盖；选 q → 一个都不下、目录无变化；**默认回车 = 跳过**。
- **依赖**：R3-B04。

### R3-B06 ｜ P1 ｜ 进度显示

- **验收**：TTY 下单行原地刷新（含 `done/n`、当前文件名、已下载/总大小、已用秒数）；非 TTY 每完成一个文件打一行；`--quiet` 不打进度但**汇总照常**；结束后进度行不残留。
- **依赖**：R3-B04。

### R3-B07 ｜ P1 ｜ 汇总与失败清单

- **验收**：成功/跳过/失败三段与 PRD §14.4 逐字；失败项写明**具体原因**（校验失败/写不进去/网络失败）；附加文件提示行 `ℹ 有 {k} 个模组…` 仅在 k>0 时出现。
- **依赖**：R3-B03。

### R3-B08 ｜ P1 ｜ 边界情况全覆盖

- **验收**：按 PRD §14.5 的 17 条逐条造场景（多数用假 fetcher）：磁盘满（monkeypatch `write` 抛 `OSError`）、无权限、目录不存在、目录是文件、网络中断、429、sha1 失败、无 `.jar`、多文件、取消。
- **依赖**：R3-B03 ~ R3-B07。

### R3-B09 ｜ P1 ｜ 预检查（空间 / 目录合法性 / 像 mods 目录的提醒）

- **验收**：剩余空间不足 → 提醒并可继续或取消；目标是文件而非目录 → ✗；目标路径像 `mods` 或含 `.minecraft` → 提醒一次并要求确认。
- **依赖**：R3-B04。

### R3-B10 ｜ P2 ｜ `settings.download_jobs` + `--download-jobs`

- **验收**：默认 3；范围 1~8；越界报错；`config show` 显示；不进交互式设置屏的首屏（高级项）。
- **依赖**：R3-B03。

### R3-B11 ｜ P1 ｜ 下载测试全套（离线）

- **验收**：`tests/test_downloader.py` 覆盖 PRD §14.5 的全部条目；**测试里不得真实联网**（假 fetcher 或 `file://` 本地服务器）。
- **依赖**：R3-B02 ~ R3-B09。

### R3-B12 ｜ P0 ｜ 共用限速器的可验证性

- **验收**：单测断言（假 clock）：把 API 请求与下载混合发起 500 次，**任意 60 秒窗口内请求数 ≤ 240**；且 `HttpClient.stats()` 的请求数包含下载。真机：下载 20 个文件时 `--debug` 输出的速率 ≤ 240/分钟。
- **依赖**：R3-B01。

## 4. 横切任务

- **验收**：在 `cmd.exe`、Windows Terminal、PowerShell 三种终端里各走一遍 [3]/[4]/[5]；再把 stdout 重定向到文件走一遍（应给"非交互"提示而不是卡死）。
