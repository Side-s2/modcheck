## 5. 结论与建议

### 5.1 是否建议交付：**不建议立即交付；只需再修一件事**

**核心功能是对的**：30 个真实模组 26.3/fabric 判定 🟢21 / 🟡7 / 🔴2 与独立基准完全一致；JourneyMap 回归、create / create-fabric、JEI 测试版、`--pre`、`--jobs` 一致性、D40 同版本号转绿全部正确；8 条一票否决 0 触发；314 条单测全绿；打包产物可用。

**唯一阻断项是 B-1 / B-2（限速与可复现）**：它是 R2 的第一优先任务，也是**唯一会在设计规模（200 模组）下让用户拿到不同结论**的问题——第一次冷跑得到 18 个「未判定」，第二次才准。程序本身是保守的（⚪ 而不是假绿），但**报告头没有提示这 18 条是限流造成的**（warnings 为空），用户很可能把第一次（不完整）报告当成最终结论去处理。

### 5.2 修复顺序

**必须修（阻断交付）**：

1. 429 条目**不落 ⚪**：按 R2-02 第 3 条做「待补跑队列 + 整轮末尾串行低速（≤60/分）重试」，仍失败才落 ⚪。
2. `report.warnings` 必须写入 PRD §12.4 第 4 条的提示句（当前为空数组），且结论行标注「本结论不完整」。
3. 消除首窗突发：初始只放行 1 个、其后按 240/60s 匀速（或限制首秒放行数），保证**任意 60 秒窗口 ≤240 且不突发**。

**建议同时修（各 1~5 行，风险低）**：B-3 坏 jar 进清单、B-4 去掉 `slug:modrinth:` / `sha1:` 前缀、B-5 JSON 异常套中文模板、B-6 重复 modid 合并 + E24、N-1（404 不计入「数据源不可用」判据）、B-7（🟡 版本列显示支持目标 MC 的版本）、D-23（`config path` 语义）。

**非阻断打磨**：B-8 窄终端折行、profile show 时间格式、README 与覆盖率（R2-24 / K4）。

### 5.3 若决定「带 B-1 交付」

必须同时满足：① 报告头**显式**列出限流项数量并建议重跑；② README「已知限制」写明「200 模组首次运行可能因 Modrinth 限流产生若干未判定，重跑一次即可」；③ 结论行标注「本结论不完整」。**否则不建议交付。**
